§6 — Columns (container + resize + creation gesture)

Design 2026-06-11
Decision: all three gestures kept over one column-row container — they are entry points, not alternatives. Build order: B (insert) → A (drag-to-edge) → C (group). Plus a draggable resize grab-handle and depth cap = 1 (v1).

Columns — the 2D layer

A column-row is one container node holding child blocks that lay out horizontally. The blocks inside keep their refs, flavours, cache & cement behaviour — the reconciler and serialiser don't notice. Refs may cross a column boundary (logical graph ≠ visual layout). Here's the target, then one decision: the creation gesture.

How do you create a column-row?

A

Drag a block to another block's edge

Grab a block's handle, drag it onto the left/right edge of another block — a drop-zone highlights and they fuse into a 2-col row. Drag more in to add columns; drag the last one out to dissolve. Most direct, most "placed-by-hand"; trickiest drop-target plumbing.

B

Explicit "columns" insert / slash command

Insert an empty 2- or 3-column layout block (slash menu or block menu), then fill each cell by typing or dragging blocks in. Predictable and easy to build; an extra step and an empty-cell state to design.

C

Select adjacent blocks → "group into columns"

Multi-select two+ stacked blocks, choose "side-by-side." Reuses the block-selection substrate we're building anyway; less spatial/fluid than dragging.
