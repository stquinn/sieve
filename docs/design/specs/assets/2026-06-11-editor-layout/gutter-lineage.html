§8 — Gutter / lineage rail (hybrid)

Design 2026-06-11
Decision: C — Hybrid. Faint always-on ‘participates’ tick + always-on dirty-glow (safety-critical); full bracket-chains + neighbour highlight on hover/select. Extends the existing block-anchor / word-highlight language — not a parallel system.

The gutter / lineage rail

References cause spooky-action-at-a-distance: edit one block, a render five screens away silently goes stale. The gutter rail is what makes that legible. It carries three things — the per-block accent + drag handle (objective 1), and bracket-chains showing ref edges (objective 3). Dirty-glow is safety-critical. Question: how loud are the edges by default?

How loud are the lineage edges by default?

A

On-demand — edges hidden until you touch a block

Quiet by default: select or hover a block and its lineage (sources + consumers) draws in the rail and highlights the related blocks. Dirty-glow is the ONLY always-on signal. Calmest; lineage is discoverable, not constant.

B

Always-on bracket-chains

Every ref edge is drawn persistently in the gutter. Maximum legibility, but a doc with many refs risks the "Christmas tree" §107 warned about.

C

Hybrid — recommended

Always-on but minimal: a faint "participates in lineage" tick in the rail + always-on dirty-glow (safety). Full bracket-chains + neighbour highlight appear on hover/select, with edited-node + immediate neighbours bright and deeper staleness dimmed. Quiet, safe, discoverable.
