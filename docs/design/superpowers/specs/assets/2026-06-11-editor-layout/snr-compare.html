§7 — Column serialization: SNR comparison

Design 2026-06-11
Direction chosen: B — one fence convention (a column-row Sieve block), not a ::: div. The low-SNR strawman shown in B here is fixed by verbatim scalar prose — see scalar-prose and block-shape for the final model.

The same column, two encodings — read the files

Target: a paragraph beside a diagram. The question is only what the on-disk markdown looks like. SNR is the whole game here.

A  :::columns thin wrapper (depth cap 1)

:::columns {widths: [0.55, 0.45]}
::col
Every request carries a bearer token. The gateway
checks the cache, then the auth service on a miss.
::col
```mermaid
Client --> Gateway --> Auth
```
:::

✓ Children are real, readable markdown. The prose is prose; the diagram is a normal mermaid fence. Strip Sieve → you read it top-to-bottom. Two thin marker lines of overhead. No :::: — ever.

B  ```column-row YAML-embed

```column-row
id: cr1
widths: [0.55, 0.45]
children:
  - kind: prose
    id: p1
    source: |
      Every request carries a bearer token. The
      gateway checks the cache, then the auth
      service on a miss.
  - kind: diagram
    id: d1
    source: |
      Client --> Gateway --> Auth
```

✗ The prose is now a YAML string. The diagram is a scalar. It's data, not a document. Every nested block re-encoded. This is the SNR collapse you flagged.

A

Thin wrapper (:::columns, no nesting in v1)

Readable children, high SNR, never emits ::::. Accept one small non-code-fence marker convention for containers only.

B

YAML-embed (one convention, low SNR)

Everything is a backtick sieve fence, but container children become YAML data and the file stops reading as a document.
